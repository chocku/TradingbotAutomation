Overview

What This Bot Does

📅 When

Fires once per day at 3:55 PM ET on NYSE trading days. Five minutes before close — enough time to fill at near-close prices.

📊 Signal

Reads QQQ daily data, computes technical indicators, and decides: hold TQQQ, hold QQQ, or go to cash.

⚡ Execute

Submits market orders via Alpaca paper/live API. Logs every run to AWS S3. Sends email notifications on start + complete.

Signal source is always QQQ. The bot never trades QQQ directly in response to a "bear" signal — it either holds TQQQ, holds QQQ (low conviction), or goes to cash.

Data Sources

What Data, From Where, and When

yfinance

QQQ Daily Bar (OHLCV)

Fetched once per run at 3:55 PM ET. Returns the official daily bar — open, high, low, close, volume. Also used to backfill the previous day's close at the start of each run, correcting any intraday proxy prices stored from earlier that session.

yfinance

VIX (^VIX) Daily Close

Fetched once per run. VIX is not available on Alpaca's free tier. Used in MR score calculation — VIX > 20 adds 1 point to the mean-reversion score, indicating elevated fear and a better buying opportunity.

Alpaca

TQQQ Latest Trade Price

Fetched from Alpaca's free IEX feed only when the signal calls for TQQQ. Used to size the position (shares = equity × allocation ÷ TQQQ price). Not used for signal computation — QQQ data drives all decisions.

Alpaca

Account Equity + Open Positions

Fetched from Alpaca Trading API. Equity is used to calculate target dollar allocation. Open positions determine current shares held and whether an instrument switch (TQQQ↔QQQ) is needed before placing the new order.

Strategy

Four-Layer Decision System

Layers are evaluated in priority order. The first layer that triggers wins — lower layers are not evaluated.

Layer 1 — SMA200 Bear Filter (highest priority)

If QQQ close < 200-day SMA → Go to cash. Full bear-market exit. Protects against 2022-style drawdowns where TQQQ lost 75%+.

Layer 2 — Candle Shock Protection

If QQQ drops >2% in one day AND closes below SMA10 → Go to cash. Stay out until price recovers above SMA10. Catches flash crashes and Fed-shock events before SMA200 reacts.

Layer 3 — SMA50 Protection Mode

If QQQ closes below SMA50 (but above SMA200) → QQQ 25%. Correction zone. Exit when price recovers above SMA50 or MR score ≥ 3.

Layer 4 — MR Score Sizing (bull mode)

Score 5 mean-reversion signals. High conviction = TQQQ 100%. Low conviction = QQQ (no leverage). Details on next slide.

Execution

Order Execution Logic

Position Sizing

Target shares = equity × allocation ÷ price.

Example: $97,000 equity, TQQQ 100%, price $75
→ Target = 1,293 shares

Delta Calculation

Delta = target shares − current shares.

Positive delta → BUY order
Negative delta → SELL order
Zero delta → no order submitted

At 100% Allocation — No Daily Rebalancing

When signal stays at 100% in the same instrument, existing shares are held as-is. No rebalancing sell. The portfolio value naturally tracks the position price. Only trades when switching instruments or buying in from cash.

Instrument Switch (TQQQ ↔ QQQ)

1. Submit SELL order for full old position → 2. Poll for fill (up to timeout) → 3. Submit BUY for new target shares. If sell fills but buy fails, error is logged and email sent — bot does not retry automatically.

Data Pipeline

How Historical Data Stays Accurate

  • Parquet files store daily QQQ OHLCV and VIX going back to June 2021 — 1,265+ rows.
  • On every run, the fetcher loads the parquet, then runs a backfill pass using yfinance to correct any rows where the stored close differs from the official daily close by more than $0.01.
  • Why backfill? When the bot runs at 3:55 PM (market still open), the "close" is a near-close proxy. The next day, yfinance provides the actual official close, and the backfill corrects the previous row.
  • Today's bar is fetched fresh from yfinance (official daily OHLCV) with Alpaca's IEX feed as a fallback if yfinance is unavailable.
  • Alpaca free tier does not allow querying recent historical daily bars (403 error). All historical corrections use yfinance instead.

Logging & Monitoring

What Gets Logged and Where

📦 AWS S3 — Trade Log

Every run appends a JSON record to trade_log.csv in S3 bucket qqq-trading-logs-chock. Fields include: timestamp, ticker, allocation %, direction, close price, equity, target shares, delta, order ID, full signal detail (all MR components), and position held before the trade.

📊 AWS S3 — Dashboard

After every run, a static HTML dashboard is generated from the trade log and uploaded to S3. Shows all historical trades, signal details, and portfolio state. Publicly accessible at the S3 URL (requires bucket to be public in AWS console).

📧 Gmail — Email Alerts

Two emails per run: Started (signal + allocation when pipeline begins) and Done (order ID, shares bought/sold, final equity). Error emails on any failure. Uses Gmail app password stored as Replit Secret.

📋 Replit — Console Logs

Full structured logging with timestamps and log levels. All pipeline steps (data fetch, strategy signal, sizing, order submission) logged with exact values. Visible in the QQQ Scheduler workflow console in the Replit IDE.

Deployment

How It's Deployed

Replit VM

Deployed as a Reserved VM on Replit (paid plan). Always running — never sleeps. No browser tab or uptime monitor needed. Production URL: trading-automation.replit.app.

start.sh

Entry point for the VM. Starts two processes:

1. healthcheck.py in background (port 8080, returns "OK")
2. main.py in foreground (APScheduler — blocks until 3:55 PM)

Manual Operations

How to Trigger Manually

--force

Runs full pipeline, bypasses calendar check. Submits real orders. Use when the scheduler missed the 3:55 PM window.

python main.py --force

--dry-run

Runs full pipeline including signal and sizing. Skips calendar check and order submission. Safe to run anytime to inspect the signal.

python main.py --dry-run

--now

Runs pipeline immediately, respects the calendar check. Will exit without trading on non-market days.

python main.py --now

Via Replit Agent

Ask: "Run now and send position" — the agent runs python main.py --force, reports the signal, order details, and confirms dashboard is updated on S3.

All commands must be run from TradingAutomation/qqq_trader/ with PYTHONPATH=/home/runner/workspace set, or via the wrapper: cd TradingAutomation/qqq_trader && PYTHONPATH=/home/runner/workspace python main.py --force
